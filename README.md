## Тестлэх функц

`POST /registrations`: оюутныг хичээлд бүртгэх. Тест бүр өөрийн setup `PUT` хүсэлтийг (`/students/:id`, `/courses/:id`) хийдэг тул бие даасан бөгөөд давтан ажиллуулахад аюулгүй. `registrationID`-ийн яг утгыг хаана ч шалгаагүй.

## Collection

`lab05-collection.json` нь 10 folder (T01-T10), 23 хүсэлттэй (13 setup `PUT` + 10 `POST /registrations`). Тест бүр өөрийн setup-тай бие даасан, статус ба `result` утгыг хоёр тусдаа oracle-оор шалгадаг. T05, T06 нь нэмэлтээр `missing` массивыг шалгадаг. Нийт **22 assertion** байна.

## Newman үр дүн

| Ажиллуулалт | Файл | Assertions executed | Failed | Exit code |
| --- | --- | --- | --- | --- |
| PASS | `results/newman-pass.txt` | 22 | 0 | 0 |
| FAIL | `results/newman-fail.txt` | 22 | 1 | 1 |
| DOWN | `results/newman-down.txt` | 22 | 22 | 1 |

README-д бичсэн **22** нь `results/newman-pass.txt`-ийн `assertions executed` тоотой таарна.

**PASS**: сервер асаалттай, бүх oracle зөв, `assertions failed 0`, `exit=0`.

**FAIL**: `lab05-collection-fail.json`-д T01-ийн oracle-ийг зориуд `status(201)`-ээс `status(200)` болгосон. Сервер 201 буцаасан тул 1 assertion унаж, `exit=1` болсон. Нэг oracle унахад exit code 0-ээс өөр болдог нь CI quality gate-ийн зарчим: pipeline-ийг автоматаар зогсоох боломжтой.

**DOWN**: сервер унтраастай үед хүсэлт бүр `ECONNREFUSED`-оор унасан, `exit=1`. Энэ нь серверт холбогдож чадаагүй интерфейсийн алдаа бөгөөд серверийн хариу ирсний дараа хүлээсэн утга таараагүй oracle-ийн алдаа (FAIL) биш.

## Дүгнэлт

Дизайны 5 алхмаас сонголтыг эквивалент ангид хуваах, төлөөлөх утга сонгох алхам хамгийн их бодол шаардсан, учир нь 4 сонголтын бүх хослолыг (3×2×2×3) шалгах боломжгүй тул 10 тест болгон цөөлөх ёстой байсан. Боломжгүй хослол таарсан: байхгүй оюутанд үзсэн хичээлийн жагсаалт утгагүй, мөн байхгүй хичээлд урьдач нөхцөл тодорхойлогдохгүй. Давхар алдааны T07, T08 тест нь серверийн шалгалтын дарааллыг илрүүлсэн: оюутныг эхэлж, хичээлийг дараа нь шалгадаг. Миний тестүүд серверт согог олоогүй, 22 assertion бүгд PASS болсон. Харин хэрэгслийн талд Postman-аас export хийсэн collection-д `baseUrl` variable хоосон гарсан тул Newman анх `Invalid URI` алдаа өгсөн, үүнийг JSON файлд утгыг нь шууд бичиж зассан. Мөн folder-ыг хуулбарлахад хуучин body, тест үлдэж T09, T10 буруу хүсэлтийг шалгаж байсныг Postman-ы Run үр дүнгээс олж зассан. Тест бүр өөрийн setup `PUT`-тай, `registrationID`-ийн яг утгыг шалгаагүй тул дарааллаас хамаарахгүй, серверийг дахин асаалгүйгээр давтан ажиллуулж болно. FAIL ажиллуулалт нэг oracle унахад exit code 1 болдгийг, DOWN ажиллуулалт `ECONNREFUSED` гарч тестийн алдаа ба интерфейсийн алдааг ялгадгийг харуулсан. Newman нь командын мөрөөс автоматаар ажилладаг тул CI pipeline-д шууд ашиглах боломжтой.
